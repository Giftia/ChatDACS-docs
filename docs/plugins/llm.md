# LLM 插件接入

源码已实现 QQ 全文本响应、LLM 内存上下文和受限单群主动聊天，并已有定向测试覆盖。本文说明当前行为与配置；授权部署、真实消息收发和云端构建结果仍需分别验证，不代表这些验收已经通过。

## QQ 文本响应

`ollama.js` 支持 Ollama 与 OpenAI 兼容服务。QQ 文本不再以 @机器人作为进入响应链路的前提，按“旧插件 → 真实语料匹配 → LLM”处理：旧插件已处理则不再生成第二条回复；只有真实语料命中才采用语料回复，未命中再交给 LLM。原有 `小夜…`、`/小夜…`、`!小夜…` 前缀仍可显式调用，不是进入 LLM 的唯一方式。

所选人设作用于 LLM 的 system 提示词，不重写旧插件或已命中的语料回复。`/更换人设`、`/查询模型`、`/更换模型` 保持各自的管理用途。

`ChatProcess` 的旧调用仍兼容原有随机兜底，新 QQ 路线不使用该随机兜底。`legacyReplyMode` 仅是 `StartQQBot` 内部注入的 options，不是新增的公开 config 字段，不需要也不应在 YAML 中配置。

## 会话上下文

上下文按平台、机器人 self 标识、会话类型及私聊用户或群分别隔离，不能跨机器人、群或私聊复用。每会话最多保留 40 条消息，有效期 2 小时；历史消息与当前 user 合计最多 16000 个 UTF-16 字符，预算不含 system 提示词，也不是精确 token 计数。字符预算可能使实际保留条数少于 40，40 条消息不等于 40 轮对话。

请求由所选人设与场景的 system、可用历史以及当前 user 组成。上下文只存内存，重启清空；切换人设清空对应会话上下文。人设/模型选择的本机持久化不等于持久化聊天记忆。

## QQ 图片对话

NapCat / OneBot 私聊和群聊的图片继续由现有 `ollama.js` 插件处理，不新增插件、指令或 HTTP 入口。支持纯图片和图片配文字，群内无需 @；仍遵守群服务与插件开关，保留旧插件和群玩法优先级。图片回答使用当前会话的模型、人设及文字上下文，纯文字请求格式不变。

每条消息最多 3 张 JPG、PNG 或 WebP；单图下载上限 4MiB，合计 8MiB，解码上限 2000 万像素。识别前自动旋转、缩放至最长边 1024px，并转换为不含原始 EXIF 的 JPEG。整批图片准备最多 5 秒，之后沿用模型请求截止时间；带图场景建议将 `System.PLUGIN_TIMEOUTS.ollama` 设为 `timeoutMs + 6000`，例如 HTTP 30000ms 时使用 36000ms，不放大其他插件的超时。

仅下载 QQ 图片 CDN 的 HTTPS 地址，不读取任意网址、本地路径或重定向；无路径的 OneBot 图片 ID 可经 `get_image` 解析，再验证 CDN 地址。识别只在内存处理图片，并将本次图片发送到配置的模型服务。后续历史仅保留 `[图片]`、配文及机器人实际发出的文字回答，不保存图片数据或签名 URL，也不重新上传旧图。原有图片转发/本地保存开关不变，启用后仍按原逻辑保存。

图片下载失败、过大、损坏或格式不支持时明确提示，不调用模型猜测。带图请求被服务以 400/415/422 拒绝时，提示当前模型或服务暂不支持图片识别，建议更换视觉模型或补充文字；这并不等于已经确定模型没有视觉能力。超时不重试，不自动换模型或回退随机语料，后续纯文字对话仍正常。模型列表不保证每个模型都有视觉能力。

验收时先在同一会话说明话题，再发图片并配问题，核对人设和文字追问；还需验证纯图片、多图及错误提示。真实 QQ 收发与手机显示须独立确认，不能以单元测试代替。

## 受限主动聊天

主动聊天仅用于已授权的单个测试群，不扩展到其他群或私聊。runtime 只接受一个群目标，多群配置会被拒绝。下面群号 `123456789` 仅为公开示例，不是实际目标或发送授权。

将以下字段合并到现有 `llm` 节，不覆盖模型、凭据等其他字段：

```yaml
llm:
  proactive:
    enabled: true
    groupIds: ['123456789'] # 仅为示例，实际目标只放在私密配置中
    minDelayMs: 600000
    maxDelayMs: 1800000
    dailyLimit: 12
    maxIdleMs: 7200000
```

只有 `enabled` 严格为布尔值 `true` 才启用；未配置或其他值均不启用。`groupIds` 默认 `[]`，未配置或为空时关闭并 fail-closed，不选择任何默认群；启用时只接受单个群号，多群配置拒绝。`maxIdleMs` 为 7200000 毫秒（2 小时），没有适合的近期上下文仍应跳过。

调度间隔为 10–30 分钟，每日最多主动发送 12 条；时区为 `Asia/Shanghai`，23:00 至次日 08:00 静默。调度不等于必须发言：没有合适上下文时跳过，模型也可以决定不发送；跳过不补发，发送失败不重发。

日常调度严格遵守静默窗口，没有公开豁免或演示 HTTP 入口。

发送前通过 NapCat 查询机器人自身的 `shut_up_timestamp` 以及群的 `group_all_shut`，确认可以发言才继续；禁言、查询失败或状态未知均 fail-closed，不发送。同时检查 LLM 和 proactive 两个插件开关，两者都允许才能发；任一关闭或状态无法确认就跳过。

日额度计数只在当前进程内存中保存，重启清空，各进程独立计数，不持久化也不跨进程共享。因此 `dailyLimit: 12` 不是跨重启或多进程合计的全局硬上限，不能通过并行实例获得一致配额保证。

保持机器人身份，不模仿人类，不回复机器人自身的消息。插件 `stop` 时清理定时器，不再继续调度发送。部署后仍须在授权范围验证这些保护与实际送达，不能仅凭定向测试宣称真实收发通过。

发送前状态查询针对 NapCat，不代表 SnowLuma 已完成真实测试。

## 模型服务配置

将下列字段合并到 `config/config.yml`，保留其他现有配置：

```yaml
System:
  PLUGIN_TIMEOUTS:
    ollama: 31000

llm:
  provider: openai
  baseUrl: https://your-server.example/v1
  model: gpt-6-luna
  apiKeyFile: config/llm.credentials.json
  timeoutMs: 30000
  modelAdminQQs: ['10001'] # 替换为你的 QQ 号
```

另在本机 `config/llm.credentials.json` 中填写 `{"apiKey":"你的密钥"}`；
也可使用优先级更高的 `CHATDACS_LLM_API_KEY` 环境变量。不要把密钥发到聊天、写入主配置或提交仓库。
凭据文件已被 Git 和发布包过滤规则排除。

客户端向 `baseUrl` 追加 `/chat/completions`，使用 Bearer 鉴权和非流式文本回复。
远程地址需要 HTTPS，本机回环地址可使用 HTTP，不跟随重定向。
模型名原样提交，不会失败后自动换模型或回退到其他服务。

HTTP 截止时间为 `timeoutMs`，范围 100–120000ms，超时取消请求且不重试。
模块软超时 `System.PLUGIN_TIMEOUTS.ollama` 建议比它多 1000ms，其他插件仍默认 8000ms。
鉴权、超时或空回复会返回安全提示，日志不记录密钥、提示词和生成正文。

## 人设切换

默认使用**小夜原生人设**。`plugins/persona/` 中的 `.txt` 文件是可选项，不会自动成为默认。
人设决定后续 LLM 请求的 system 提示词；切换时清空对应会话上下文，不影响其他会话，也不会重写已匹配的旧语料回复。

- `/更换人设`：列出可用文件及序号，0 为原生。
- `/更换人设 查看`：查看当前人设。
- `/更换人设 大肥鱼女友版.txt`：按文件名切换，也可使用列表序号。
- `/更换人设 重置`：恢复小夜原生，也可选择 0。

选择按私聊或群聊独立保存，群内切换不影响其他群和私聊。默认状态文件为本机
`config/llm-persona-state.json`，会话标识以哈希保存，Git 与发布包均排除此文件。
可通过 `llm.personaDir`、`llm.personaStateFile` 修改位置，状态文件父目录需已存在。
每个状态文件只供一个运行实例写入；同时运行正式程序和插件测试器时，必须使用不同状态文件。
仅支持目录直属普通 `.txt` 文件，拒绝路径遍历和符号链接，文件上限 128KiB；
选中文件删除后恢复原生，状态文件损坏时返回错误而不覆盖。人设作为 system 消息发送，
当前发言作为 user 消息；可用聊天历史仅按前述内存上下文规则保留，不写入人设状态文件。

## 模型查询与切换

- `/查询模型`：列出第一页，每页 10 个；`/查询模型 2` 查看第二页。
- `/查询模型 luna`、`/查询模型 luna 2`：按关键词筛选和翻页。
- `/更换模型 查看`：查看当前会话模型。
- `/更换模型 完整模型ID`：切换当前会话；`/更换模型 重置` 恢复默认。

所有用户可查询，只有 `llm.modelAdminQQs` 配置的 QQ 账号可修改或重置。
不配置就不授予修改权限；相同数字 ID 的 Web 用户等不会因此获得 QQ 管理权限。
私聊和群聊各自保存，不改变其他会话、人设或全局默认模型。
服务模型目录缓存 60 秒，查询不调用生成。默认模型单独展示，未列出的配置默认别名仍可恢复使用。
目录是服务公布的模型，并未逐一验证额度和连通性；响应上限 2MiB，最多收录 5000 个 ID。
选择其他模型前必须存在于服务目录；调用失败不会自动替换模型或服务。

模型状态保存在本机 `config/llm-model-state.json`，也可设置 `llm.modelStateFile`，
该文件同样被 Git 和发布包排除。父目录需存在，每个状态文件仅供一个实例写入。

## 兼容与验收

没有 `llm` 配置时继续使用旧 `llamaUrl` 和 `model`，旧 Ollama 问句降级行为不变。

1. 在授权测试会话中，不 @机器人、不加“小夜”前缀，发送一条确认未命中旧插件或本地语料的问题，例如“我给纸飞机起名为蓝莓，请帮我想一句口号”。核对路由确实进入 LLM，而不是随机兜底。
2. 在同一会话追问“刚才纸飞机叫什么名字？”，检查能否使用该会话历史；在另一群或私聊验证不串上下文，在隔离实例中验证重启和切换人设会清空相应记录。
3. 用 mock 或隔离测试验证主动保护：双插件开关、禁言及未知状态、静默窗口、无合适上下文、模型决定不发、多群拒绝、日额度和 stop 清定时器。不为测试绕过日常静默规则。
4. 只有获准部署和发送后，才在授权单群验证实际通知，分别核对模型结果、OneBot 回执及手机显示。本文和定向测试不代表手机已收到，也不代表云端构建通过。
